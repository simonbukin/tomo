tomo

A little workspace for coding agents.

Run many agents at once and the mess is not the code. It is the room: which worktree, which terminal, which agent waits for you, which one eats the machine.

Tomo keeps that room in order. The worktree is the unit. Terminals, agents, processes, ports, and attention all roll up to it. Tomo does not replace Git, your editor, your shell, or your agents. It keeps the room organized.

shape

tomod
A local Rust daemon. It owns the terminals, the state, and the agent signals.
tomo
A command-line client. Agents and shell scripts speak to Tomo through it.
Tomo.app
A desktop window. It is a view, and nothing more.

Close the window and nothing dies. Open it again and everything reconnects.

how it thinks

  • Yours to change. Read the source, change it, build it. A tool you cannot open is a tool you rent.
  • Small parts that compose. The daemon holds the truth. The CLI is the whole API. The window is disposable. Each part stays useful when you ignore the others.
  • Addons, not a plugin API you must beg for. The core stays small on purpose. An addon adds its own state, its own commands, and its own place in the window, and a test keeps the core from learning its name.
  • Local, and quiet about it. Everything runs on your machine. No account, no cloud, no telemetry. The daemon makes no calls of its own.
  • Fast enough to forget. A tool you wait for is a tool you stop opening.
  • Quiet by default. It should feel like good stationery: careful, restrained, tactile. It tells you what needs you, and otherwise says nothing.

measured, not claimed

install

git clone https://github.com/simonbukin/tomo
cd tomo
scripts/install.sh
tomo integrations install

The script builds the binaries, puts tomo and tomod in ~/.local/bin, and puts the app in /Applications. The last line adds the hooks for Claude, Codex, and Pi.

macOS only today. The daemon speaks over a Unix socket, so Linux is close but untested, and Windows needs a different transport first.
